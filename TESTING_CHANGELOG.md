# Testing the Changelog Automation Pipeline

This guide shows you how to test the changelog automation system step by step.

## 🧪 Option 1: Local Testing (Recommended First Step)

Test the script locally before pushing to GitHub.

### Prerequisites

1. **Install Kotlin** (if not already installed):
   ```bash
   # macOS
   brew install kotlin
   
   # Or download from https://kotlinlang.org/docs/command-line.html
   ```

2. **Get an LLM API Key** (if you want to test LLM integration):
   - **YandexGPT**: Get IAM token from Yandex Cloud (see `YANDEXGPT_SETUP.md`)
   - **OpenAI**: Sign up at https://platform.openai.com/ and create API key
   - **Note**: You can test without the API key (it will use commit message as fallback)

### Step 1: Test Basic Functionality (No API Key Needed)

```bash
cd /Users/Girev.Aleksandr2/AndroidStudioProjects/AIChat

bash scripts/generate-changelog-entry.sh \
  --commit-hash "abc1234" \
  --commit-message "[TKT-123] Fix notification crash on Android 14" \
  --kb-url "https://httpbin.org/post"
```

**Expected Output:**
- Script runs without errors
- Creates `changelog-entry.json` file
- Shows ticket ID: `TKT-123`
- Shows app version: `1.0`
- Shows task description (from commit message since no API key)
- Sends data to httpbin.org (you'll see a success message)

**Check the output:**
```bash
cat changelog-entry.json
```

You should see:
```json
{
  "timestamp": "2025-01-18T...",
  "app_version": "1.0",
  "ticket_id": "TKT-123",
  "task_description": "Fix notification crash on Android 14",
  "commit_hash": "abc1234"
}
```

### Step 2: Test with YandexGPT API (Full Functionality)

```bash
# Replace with your actual YandexGPT credentials
export LLM_API_KEY="t1.your-iam-token"
export LLM_FOLDER_ID="b1gxxx-your-folder-id"

bash scripts/generate-changelog-entry.sh \
  --commit-hash "def5678" \
  --commit-message "[PROJ-456] Add dark mode support for settings screen" \
  --llm-api-key "$LLM_API_KEY" \
  --llm-provider "yandexgpt" \
  --llm-folder-id "$LLM_FOLDER_ID" \
  --kb-url "https://httpbin.org/post"
```

**Or test with OpenAI:**

```bash
export LLM_API_KEY="sk-your-openai-key"

bash scripts/generate-changelog-entry.sh \
  --commit-hash "def5678" \
  --commit-message "[PROJ-456] Add dark mode support" \
  --llm-api-key "$LLM_API_KEY" \
  --llm-provider "openai" \
  --kb-url "https://httpbin.org/post"
```

**Expected Output:**
- Task description is generated by LLM (more polished than raw commit message)
- All other fields populated correctly

## 🚀 Option 2: Test with GitHub Actions (Dry Run)

Test the GitHub Actions workflow without pushing to main branch.

### Step 1: Create a Test Branch

```bash
git checkout -b test-changelog-automation
```

### Step 2: Configure GitHub Secrets

1. Go to your GitHub repository
2. Navigate to: **Settings → Secrets and variables → Actions**
3. Click **New repository secret**
4. Add these secrets:

   | Secret Name | Value | Required |
   |------------|-------|----------|
   | `LLM_API_KEY` | `t1.xxx...` (YandexGPT) or `sk-...` (OpenAI) | Yes (for LLM) |
   | `LLM_FOLDER_ID` | `b1gxxx...` (required for YandexGPT) | Yes* |
   | `KB_API_URL` | `https://httpbin.org/post` | No (default) |
   | `KB_API_KEY` | (leave empty for httpbin) | No |

   \* Required only if using YandexGPT (set `LLM_PROVIDER=yandexgpt` variable)

### Step 3: Create a Test Commit

```bash
# Make a small change
echo "# Test changelog automation" >> TEST.md

# Commit with proper format
git add TEST.md
git commit -m "[TKT-999] Test changelog automation pipeline"

# Push to test branch
git push origin test-changelog-automation
```

### Step 4: Trigger Workflow Manually

1. Go to your GitHub repository
2. Click **Actions** tab
3. Find **Generate and Send Changelog Entry** workflow
4. Click **Run workflow** → Select `test-changelog-automation` branch → **Run workflow**

### Step 5: Check Workflow Results

1. Click on the running workflow
2. Expand **Generate changelog entry** step
3. Look for:
   - ✓ App version extracted
   - ✓ Ticket ID parsed
   - ✓ Task description generated
   - ✓ Successfully sent to knowledge base

4. Expand **Display generated changelog** step
5. You should see the JSON output

## 🐛 Troubleshooting

### Problem: "curl: command not found"

**Solution:**
```bash
# macOS
brew install curl

# Linux (Ubuntu/Debian)
sudo apt-get install curl

# The script uses bash and curl, which are standard on most systems
```

### Problem: "LLM API key not provided" warning

**Solution:** This is expected if you don't provide an API key. The script will use the commit message as fallback. To test LLM integration:
- For YandexGPT: Add `--llm-api-key "t1.xxx" --llm-folder-id "b1gxxx"`
- For OpenAI: Add `--llm-api-key "sk-..." --llm-provider "openai"`

### Problem: GitHub Actions workflow fails

**Check:**
1. Are secrets configured? (Settings → Secrets and variables → Actions)
2. Is the commit message format correct? (should match pattern)
3. Check workflow logs for specific error messages
4. Verify `app/build.gradle.kts` exists and has `versionName`

### Problem: Can't see workflow in Actions tab

**Solution:**
- Make sure you pushed to `main` or `master` branch
- Or manually trigger from Actions → Run workflow
- Check that `.github/workflows/update-changelog.yml` exists in your repository

## 📝 Quick Test Script

Save this as `test-changelog.sh` and run it:

```bash
#!/bin/bash
set -e

echo "🧪 Testing Changelog Automation..."
echo ""

echo "1️⃣ Testing basic functionality..."
bash scripts/generate-changelog-entry.sh \
  --commit-hash "test123" \
  --commit-message "[TKT-123] Test changelog generation" \
  --kb-url "https://httpbin.org/post"

echo ""
echo "2️⃣ Checking output file..."
if [ -f changelog-entry.json ]; then
  echo "✅ changelog-entry.json created!"
  cat changelog-entry.json
  echo ""
  echo "✅ Test passed!"
else
  echo "❌ changelog-entry.json not found!"
  exit 1
fi
```

Make it executable and run:
```bash
chmod +x test-changelog.sh
./test-changelog.sh
```
