# Устранение проблем с Ollama

## Проблема: Модель загружена, но API не видит её

### Симптомы
- `ollama list` показывает модель
- `curl http://server:11434/api/tags` возвращает пустой список
- `curl .../api/generate` возвращает ошибку "model not found"

### Решение

**Причина:** Сервер Ollama нужно перезапустить после загрузки модели, чтобы он обновил список доступных моделей.

**Шаги:**

1. **Остановить текущий процесс Ollama:**
   ```bash
   # Найти процесс
   ps aux | grep ollama
   
   # Остановить (замените PID)
   kill <PID>
   # или
   pkill ollama
   ```

2. **Запустить снова:**
   ```bash
   export OLLAMA_HOST=0.0.0.0:11434
   ollama serve &
   ```

3. **Проверить:**
   ```bash
   # С сервера
   curl http://localhost:11434/api/tags
   
   # Извне
   curl http://193.42.127.171:11434/api/tags
   ```

### Альтернативное решение (без перезапуска)

Иногда помогает "прогрев" модели - первый запрос к модели заставит Ollama её обнаружить:

```bash
# С сервера выполните первый запрос
curl http://localhost:11434/api/generate -d '{
  "model": "qwen2:7b-instruct",
  "prompt": "test",
  "stream": false
}'
```

После этого модель должна появиться в списке.

## Другие распространенные проблемы

### Проблема: Connection refused

**Причина:** Ollama слушает только на localhost

**Решение:**
```bash
export OLLAMA_HOST=0.0.0.0:11434
pkill ollama
ollama serve &
```

### Проблема: Модель не загружается

**Возможные причины:**
- Недостаточно места на диске
- Проблемы с сетью
- Неверное имя модели

**Решение:**
```bash
# Проверить место на диске
df -h

# Проверить доступные модели
ollama list

# Попробовать другую модель
ollama pull llama3.2:1b
```

### Проблема: Медленные ответы

**Причины:**
- Модель работает на CPU (без GPU)
- Недостаточно RAM
- Большая модель для доступных ресурсов

**Решение:**
- Использовать меньшую модель (1b-3b вместо 7b+)
- Увеличить RAM
- Использовать GPU (если доступен)

### Проблема: Порт занят

**Ошибка:** `bind: address already in use`

**Решение:**
```bash
# Найти процесс, использующий порт
sudo lsof -i :11434
# или
sudo netstat -tlnp | grep 11434

# Остановить процесс
kill <PID>
```

## Проверка работоспособности

Полная проверка после настройки:

```bash
# 1. Проверить версию
curl http://193.42.127.171:11434/api/version

# 2. Проверить список моделей
curl http://193.42.127.171:11434/api/tags

# 3. Проверить генерацию
curl http://193.42.127.171:11434/api/generate -d '{
  "model": "qwen2:7b-instruct",
  "prompt": "Привет!",
  "stream": false
}'
```

Или используйте скрипт проверки из проекта:

```bash
./scripts/check-ollama-remote.sh http://193.42.127.171:11434 qwen2:7b-instruct
```
