# Руководство по использованию реранкера и фильтрации RAG

## Обзор

В RAG-систему добавлены следующие функции:
1. **Второй этап реранкинга** - фильтрация результатов после векторного поиска
2. **Сравнение ответов** - сравнение качества ответов с фильтром и без фильтра
3. **Настройка порогов** - возможность настройки порогов отсечения в runtime

## Команды

### Управление RAG

```
/rag on              - Включить RAG
/rag off             - Выключить RAG
/rag status          - Показать статус RAG и текущие настройки
```

### Настройка порогов

```
/rag threshold <0.0-1.0>           - Установить порог схожести для векторного поиска (по умолчанию: 0.5)
/rag rerank-threshold <0.0-1.0>    - Установить порог для реранкера (по умолчанию: 0.0, отключен)
```

**Примеры:**
```
/rag threshold 0.3        - Установить порог схожести 0.3 (более мягкий фильтр)
/rag rerank-threshold 0.6 - Установить порог реранкера 0.6 (более строгий фильтр)
```

### Управление реранкером

```
/rag reranker on   - Включить второй этап реранкинга
/rag reranker off  - Выключить второй этап реранкинга
```

### Сравнение ответов

```
/rag compare <ваш вопрос>
```

Эта команда генерирует два ответа:
1. **Без реранкера** - использует только векторный поиск
2. **С реранкером** - использует векторный поиск + второй этап фильтрации

Позволяет сравнить качество ответов и выбрать оптимальные настройки.

**Пример:**
```
/rag compare Какой мой любимый цвет?
```

## Как это работает

### Двухэтапный процесс поиска

1. **Первый этап (векторный поиск):**
   - Поиск по векторным эмбеддингам с использованием cosine similarity
   - Фильтрация по порогу `minSimilarity`
   - Получение начального списка результатов

2. **Второй этап (реранкинг):**
   - Дополнительная фильтрация результатов
   - Применение порога `rerankThreshold`
   - Возможность улучшения ранжирования на основе дополнительных критериев
   - Ограничение количества результатов

### Настройка порогов

- **minSimilarity** (порог схожести):
  - Более низкое значение (0.0-0.3) = больше результатов, но менее релевантных
  - Более высокое значение (0.7-1.0) = меньше результатов, но более релевантных
  - Рекомендуемое значение: 0.3-0.6

- **rerankThreshold** (порог реранкера):
  - Используется для дополнительной фильтрации после векторного поиска
  - 0.0 = отключен (все результаты проходят)
  - Более высокое значение = более строгая фильтрация
  - Рекомендуемое значение: 0.0-0.5

## Примеры использования

### Пример 1: Настройка для более точных результатов

```
/rag threshold 0.6
/rag rerank-threshold 0.5
/rag reranker on
```

Это даст более точные, но менее разнообразные результаты.

### Пример 2: Настройка для более широкого охвата

```
/rag threshold 0.3
/rag rerank-threshold 0.0
/rag reranker off
```

Это даст больше результатов, но может включать менее релевантные.

### Пример 3: Сравнение качества

```
/rag compare Какой мой рост?
```

Сравните оба ответа и выберите, какой лучше подходит для ваших задач.

## Технические детали

### Реранкер

Реранкер (`RelevanceReranker`) выполняет:
- Фильтрацию по порогу схожести
- Сортировку результатов по убыванию релевантности
- Ограничение количества результатов
- Возможность расширения с дополнительными критериями (длина чанка, метаданные и т.д.)

### Сравнение ответов

Функция `compareAnswersWithFilter()`:
- Генерирует ответ без реранкера
- Генерирует ответ с реранкером
- Возвращает оба ответа для сравнения
- Показывает использованные пороги

## Рекомендации

1. **Начните с настройки по умолчанию** и оцените качество
2. **Используйте `/rag compare`** для тестирования разных порогов
3. **Настройте пороги** в зависимости от ваших данных:
   - Для технической документации: более высокие пороги (0.6-0.8)
   - Для общих вопросов: более низкие пороги (0.3-0.5)
4. **Экспериментируйте** с включением/выключением реранкера
